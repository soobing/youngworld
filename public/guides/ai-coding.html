1채팅 vs 에이전트

요즘 AI는 코딩을 도와줘요. 그런데 쓰는 방법이 두 가지예요. 둘 다 속은 같은 AI(LLM)인데, 차이는 '어떻게 쓰느냐'죠.

🍳 비유: 채팅은 옆에서 레시피를 알려주는 친구, 에이전트는 주방에 들어와 같이 요리해 주는 친구예요.
🧠 알아두기: 코딩 에이전트도 속은 LLM이 움직여요. '채팅'은 그 AI가 말로 답하는 것, '에이전트'는 그 AI에게 손(도구)을 쥐여줘 직접 파일을 고치게 한 거예요.
구분LLM 채팅 서비스코딩 에이전트
예시ChatGPT, Claude 앱Claude Code, Codex
일하는 곳웹/앱 대화창내 실제 프로젝트 폴더 안
코드 반영내가 복사해서 붙여넣기AI가 파일을 직접 수정·실행
잘하는 일설명, 아이디어, 짧은 코드여러 파일을 아우르는 실제 작업

누가 만들까 — 회사와 서비스

우리가 쓰는 AI들은 서로 다른 회사가 만들어요. 그리고 회사마다 채팅용과 코딩용을 따로 내놓죠. 이름이 비슷비슷해서 헷갈리기 쉬운데, 표로 보면 규칙이 보여요.

만든 회사💬 채팅 서비스🤖 코딩 에이전트
Anthropic (앤스로픽)Claude 클로드Claude Code ← 이번 실습에서 사용
OpenAI (오픈에이아이)ChatGPT 챗지피티Codex 코덱스
Google (구글)Gemini 제미나이Gemini CLI

표를 세로로 보면 회사가 보이고, 가로로 보면 같은 회사의 두 가지 얼굴이 보여요. 그러니까 이런 뜻이에요 — Claude와 Claude Code는 경쟁 상대가 아니라 형제, ChatGPT와 Codex도 형제랍니다.

같은 AI, 두 가지 옷 — Claude vs Claude Code

가장 많이 헷갈리는 부분이에요. 결론부터 말하면 속(뇌)은 같고, 겉(손)이 달라요.

비교💬 Claude (채팅)🤖 Claude Code (에이전트)
어디서 켜요?브라우저·휴대폰 앱터미널(명령어를 치는 까만 창)
뭘 볼 수 있어요?내가 붙여넣은 것만내 프로젝트 폴더 전체
뭘 할 수 있어요?글·그림·아이디어로 답하기파일 읽기·고치기·실행하기
잘 어울리는 일숙제 도움, 글쓰기, 개념 질문실제 프로그램 만들고 고치기
🎭 비유: 같은 사람이 교실에서는 학생이고 축구장에서는 선수인 것과 같아요. 사람은 그대로인데 있는 장소와 할 수 있는 일이 다르죠. ChatGPT와 Codex, Gemini와 Gemini CLI도 정확히 같은 관계예요.
🔬 한 걸음 더: '모델'과 '서비스'도 다른 말이에요. 모델은 뇌 자체, 서비스는 그 뇌를 쓰게 해주는 앱이나 프로그램이에요. 한 회사가 크기가 다른 모델을 여러 개 만들기도 해요 — 빠르고 가벼운 모델, 느리지만 아주 똑똑한 모델처럼요. 어려운 문제일수록 똑똑한 모델을 쓰는 거죠.

2이번 실습에서 Claude를 고른 이유

이번 수업에서는 코딩 에이전트 Claude Code로 실제 게임을 함께 만들어요. 이유는 이래요.

  1. 프로젝트 전체를 이해해요. 파일 하나가 아니라 게임 전체를 읽고, 맥락에 맞게 고쳐 줘요.
  2. 읽기 → 고치기 → 실행까지 한 번에 해요. 결과를 바로 확인하며 배울 수 있어요.
  3. 안전장치가 있어요. 위험하거나 되돌리기 어려운 일은 먼저 물어보고 진행해서, 처음 배우는 사람도 안심돼요.
  4. 한국어 설명이 자연스러워요. 왜 그렇게 고쳤는지 친절히 알려줘요.
  5. 이 게임(영월드)이 실제 증거예요. 여러분이 지금 하고 있는 이 게임도 Claude와 함께 만들었어요!
💡 도구는 도구일 뿐이에요. 가장 중요한 건 무엇을 왜 만들지 생각하는 사람, 바로 여러분이에요. AI는 그 생각을 빠르게 도와주는 친구랍니다.

여기까지가 "AI로 코딩한다"의 기본이에요. 이제부터는 실제로 만들 때 쓰는 세 가지 기능이에요. 이름은 어려워 보여도 뜻은 아주 단순해요.

3서브에이전트 — 일을 나눠 맡기는 도우미들

할 일이 많으면 혼자보다 여럿이 낫죠. 서브에이전트(subagent)는 AI가 자기 도우미 AI를 불러서 일을 나눠 맡기는 기능이에요.

👥 비유: 모둠 과제와 똑같아요. 조장이 "너는 자료 조사, 너는 발표자료, 너는 검토" 하고 나눠 맡기면 훨씬 빨리 끝나죠. 각자 자기 노트에 정리하고, 조장에게는 정리된 결과만 가져와요.

왜 나눠 맡기면 좋을까?

⚡ 동시에 진행돼요

세 가지 일을 하나씩 하지 않고 한꺼번에 진행해요.

🧹 대화가 안 지저분해져요

중간 과정(파일 100개 읽기 등)은 도우미 쪽에 남고, 대장에겐 결론만 와요.

🎯 전문가를 만들 수 있어요

"영상 만드는 도우미"처럼 한 가지만 잘하는 도우미를 미리 정해둘 수 있어요.

🔒 권한을 좁힐 수 있어요

도우미마다 쓸 수 있는 도구를 정해줘요. 읽기만 가능한 도우미도 만들 수 있죠.

영월드에 진짜 있는 도우미

이 프로젝트에는 dream-film 이라는 도우미가 실제로 등록돼 있어요. 하는 일은 이래요 — 자기소개 글을 읽고 → 5컷 이야기를 짜고 → 그림을 받아 26초짜리 영상으로 만들어 → 교실 갤러리에 걸기.

도우미를 만드는 방법은 의외로 간단해요. .claude/agents/ 폴더에 파일 하나를 만들고 이름 · 무슨 일을 하는지 · 어떤 도구를 쓸 수 있는지를 적으면 끝이에요. 그다음부터는 "나의 꿈은 영상 만들어줘" 라고 말하기만 하면 대장이 알아서 이 도우미를 부릅니다.

🧩 핵심: 서브에이전트는 새로운 AI가 아니에요. 같은 AI에게 따로 방을 하나 내주고 역할을 정해준 것뿐이에요.

4resume — 어제 하던 대화를 오늘 이어서

게임 만들다가 시간이 다 됐어요. 내일 이어서 하려면 "우리가 뭘 하고 있었는지"를 처음부터 다시 설명해야 할까요? 아니에요. resume(이어하기)가 있거든요.

🎮 비유: 게임의 이어하기랑 똑같아요. 매번 처음 스테이지부터 다시 하지 않고, 저장된 지점에서 시작하죠. 캐릭터 레벨도 아이템도 그대로!

쓰는 방법 — 명령어 두 개

claude --continue # 가장 최근에 하던 대화를 바로 이어서 claude --resume # 지난 대화 목록에서 골라서 이어서

--continue 는 "아까 그거 계속!"이고, --resume 은 "지난주에 하던 그거 다시 열어줘"예요. 목록에서 원하는 대화를 고르면 그때 나눴던 이야기, 고쳤던 파일, 정했던 규칙이 전부 그대로 살아납니다.

왜 이게 중요할까?

AI는 대화 내용을 기억해서 일을 해요. 그래서 대화가 이어질수록 "우리 프로젝트는 이렇게 생겼고, 이런 규칙이 있고, 아까 이걸 고쳤다"는 걸 점점 더 잘 알게 되죠. 새 대화를 열면 그 기억이 0에서 다시 시작이에요. 이어하기를 쓰면 그동안 쌓은 걸 그대로 가져갈 수 있어요.

노트북이 바뀌면? — 수련관에서 집으로

이런 상황이 진짜 자주 생겨요. 수련관 노트북으로 게임을 만들다가 시간이 끝났어요. 집에 와서 내 노트북으로 이어서 하고 싶어요. 그냥 claude --resume 을 치면 될까요?

아니요. 여기서 아주 중요한 걸 알게 돼요 — 코드와 대화 기록은 따로 움직여요.

🎒 비유: 대화 기록은 교실 사물함에 둔 노트예요. 집에 간다고 사물함이 따라오진 않죠. 반면 코드는 클라우드에 올려둔 파일이라 어디서든 열려요. 그래서 집에 가기 전에 노트의 중요한 내용을 옮겨 적어 가방에 넣어야 해요.
같은 노트북에서 이어할 때다른 노트북에서 이어할 때
코드그대로 있어요git pull로 가져와요
대화 기록--resume으로 그대로 살아나요안 따라와요 — 메모로 대신해요
미리 할 일없어요끝낼 때 메모 남기고 올리기

그래서 이렇게 해요 — 이어달리기 메모

  1. 수련관에서 끝낼 때 — Claude에게 "오늘 뭘 했고 다음에 뭘 할지 정리해 줘"라고 부탁하고, 그 내용을 프로젝트 안에 NOTES.md 같은 파일로 저장해요.
  2. 코드와 메모를 함께 올려요 — git push. 이제 메모도 코드의 일부라서 같이 따라와요.
  3. 집에서 내려받아요 — git pull 로 최신 코드를 가져와요.
  4. 새 대화를 열고 메모를 읽혀요 — "NOTES.md 읽고 이어서 하자" 한마디면, 새 노트북의 Claude가 어디까지 했는지 파악하고 이어갑니다.
  5. 그다음부터는 집 노트북에서 claude --continue 로 편하게 이어가면 돼요.
📌 핵심: AI의 기억에는 두 종류가 있어요. 대화 기록은 그 컴퓨터에만 남는 임시 기억, 코드와 문서에 적어둔 것은 어디서나 따라오는 진짜 기억이에요. 중요한 건 파일로 남겨야 살아남아요.
🧑‍🏫 수업 팁: 실습이 끝날 때마다 "지금까지 한 일과 다음에 할 일을 정리해 줘"를 습관처럼 해보세요. 같은 노트북이면 이어하기가 더 매끄러워지고, 노트북이 바뀌어도 그 메모 하나로 이어갈 수 있어요.

5worktree — 여러 갈래를 동시에 작업하기

친구 세 명이 같은 게임을 동시에 고치면 어떻게 될까요? 한 폴더에서 다 같이 고치면 서로 덮어써서 엉망이 돼요. worktree(작업 나무)는 같은 프로젝트를 여러 폴더로 펼쳐 놓는 방법이에요.

📓 비유: 모둠 신문을 만드는데 종이 한 장에 네 명이 동시에 쓰면 글씨가 겹치죠. 대신 각자 자기 종이에 쓰고 마지막에 한 장으로 붙이면 깔끔해요. worktree가 바로 그 '각자 자기 종이'예요.

그냥 폴더를 복사하면 안 되나요?

좋은 질문이에요. 복사해도 작업은 돼요. 문제는 그다음이에요.

폴더를 복사하면 복사본은 그냥 파일 뭉치가 돼요. 원본과 아무 관계가 없는 남남이죠. 그래서 이런 일이 생겨요.

  1. 내가 뭘 바꿨는지 아무도 몰라요 — 원본과 복사본을 나란히 놓고 한 줄씩 눈으로 비교해야 해요. 파일이 100개면요? 상상만 해도 아찔하죠.
  2. 다시 합칠 방법이 없어요 — 통째로 덮어쓰면 그동안 친구가 고친 게 전부 날아가요.
  3. 지금까지의 기록도 안 따라와요 — 누가 언제 무엇을 고쳤는지 볼 수 없어요.

worktree로 펼친 폴더는 달라요. 이 폴더는 "나는 저 저장소에서 나온 폴더야" 라는 걸 알고 있어요. 그래서 내가 고친 부분만 자동으로 표시되고, 다 끝나면 원래 자리로 돌려보낼 수 있어요.

📓 비유: 친구 노트를 사진 찍어 가면 내가 거기에 뭘 적어도 친구 노트에는 아무 일도 안 일어나죠. 나중에 "내가 뭘 더 적었는지" 알려주려면 두 노트를 나란히 놓고 한 줄씩 비교해야 해요. worktree는 누가 언제 무엇을 적었는지 저절로 기록되는 노트를 나눠 쓰는 것과 같아요.
git worktree add ../새폴더 브랜치이름 # 새 작업 폴더를 하나 펼친다 git worktree list # 지금 펼쳐진 폴더들 보기

여기서 나온 브랜치(가지)와 합치기가 뭔지는 책장의 「개발자는 어떻게 함께 일할까?」 ↗ 문서에서 자세히 다뤄요. 지금은 "작업 갈래마다 폴더를 따로 준다" 정도만 기억하면 충분해요.

🌏 진짜 이야기: 지금 읽고 있는 이 문서도 develop-lecture 라는 worktree 폴더에서 만들어졌어요. 같은 시간에 옆 폴더에서는 다른 문서가 만들어지고 있었고요!

6정리 — 언제 뭘 쓰면 될까?

이름이 비슷비슷해서 헷갈리기 쉬워요. 한 줄로 구분해 볼게요.

기능한 줄 요약이럴 때 써요
서브에이전트AI가 도우미 AI에게 일을 나눠 맡김할 일이 여러 갈래이거나, 특정 작업 전문가가 필요할 때
resume지난 대화를 그대로 불러와 이어감어제 하던 걸 오늘 계속할 때
worktree같은 프로젝트를 여러 폴더로 펼침서로 다른 작업을 동시에 진행할 때

세 가지 모두 목적은 같아요 — 일을 잘게 나누고, 흐름이 끊기지 않게 하는 것. 사람도 똑같죠. 혼자 다 하지 않고 나눠 맡기고, 하던 자리를 표시해 두고, 서로 부딪히지 않게 자리를 따로 쓰면 훨씬 잘 굴러가요.

🚀 마지막으로: AI는 도구고, 그 도구를 어떻게 쓸지 정하는 건 여러분이에요. "무엇을 만들까?"라는 질문에 답할 수 있는 건 지금도, 앞으로도 사람이랍니다.
