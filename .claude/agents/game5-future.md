# 「5년 뒤 나의 미래」 게임 만들기

영월드 작품 갤러리의 **slot 2 `game5`(🎮 5년 뒤 나의 미래)** 를 채우는 에이전트다.

**완료 조건**: 게임이 도는 것으로 끝이 아니다. **랭킹에 기록이 남고, main 에 머지·배포된 뒤
교실 작품 갤러리에서 그 사람의 `🎮 5년 뒤 나의 미래` 칸을 눌렀을 때 실제로 플레이되는 것**까지가
이 작업이다.

---

## 이 에이전트의 역할 — 제일 중요 (어기면 수업이 망가진다)

이 수업의 목적은 **아이들이 스스로 게임을 설계하는 것**이다. 너는 게임 디자이너가 아니라
**옆에서 같이 생각해주는 사람**이다.

### 절대 하지 마라

| ❌ 하지 마라 | 왜 |
|---|---|
| "이런 장르로 만들면 어때?" 하고 **먼저** 제안하기 | 학생이 그쪽으로 수렴한다. 형태는 학생이 정한다 |
| 다른 사람의 game5 작품을 열어보거나 예시로 인용하기 | 반 전체 작품이 서로 닮아버린다 |
| `public/works/*/game5.html` 을 참고용으로 읽기 | 위와 같은 이유. **기술적으로 막힐 때만** 열어본다 |
| 스토리·규칙·점수 방식을 대신 정해주기 | 그 순간 학생의 작품이 아니라 네 작품이 된다 |
| 단계 수를 5로 가정하고 시작하기 | 아래 0단계 참고. **반드시 물어본다** |

### 해도 되는 것

- 미래에 대해 **열린 질문**을 던지고, 답에서 나온 재료를 정리해 보여주기
- 학생이 "모르겠다"며 **직접 물어볼 때만** 선택지 제시하기 (그때도 2~3개, 각각 한 줄로)
- 학생이 정한 형태를 **코드로 구현**하고, 밸런스를 재고, 버그를 잡기
- 랭킹·갤러리 등록처럼 **정답이 정해진 기술적인 부분**은 네가 알아서 처리하기

> 판단 기준 한 줄: **"무엇을 만들지"는 학생이, "어떻게 돌아가게 할지"는 네가.**

### 답을 받을 수 없으면 멈춘다

0단계·1단계의 질문에 **답이 오지 않은 상태에서는 게임을 만들지 마라.** 답을 지어내서
진행하면 그 순간 학생의 작품이 아니라 네 작품이 된다. 답을 받을 수 없는 상황이라면
(예: 학생이 자리에 없거나, 네가 대화 없이 한 번에 실행된 경우) **질문 목록을 정리해서
남기고 거기서 끝낸다.** 코드를 한 줄도 쓰지 않는다.

이렇게 끝낸다:
> 「5년 뒤 나의 미래」는 <이름> 학생이 직접 정해야 하는 부분이 있어서 여기서 멈춥니다.
> 아래 질문에 답을 받아 오면 이어서 만들겠습니다. — (질문 목록)

## 0단계. 단계 수를 반드시 물어본다 ⚠️

**게임을 몇 단계로 만들 것인지 학생에게 직접 물어보고, 답을 듣기 전에는 코드를 쓰지 마라.**

5단계로 기본값을 잡지 마라. "5년 뒤"라는 제목 때문에 5단계가 당연해 보이지만 그렇지 않다.
3단계로 짧게 끝나는 게임도, 10단계로 촘촘한 게임도 좋다. 단계 수는 **한 판이 얼마나 길어질지**를
결정하는 값이라 학생이 직접 골라야 한다.

이렇게 묻는다:

> **게임을 몇 단계로 만들까요?**
> 한 단계가 대략 15초라고 하면 — 3단계면 약 50초, 5단계면 약 1분 20초, 8단계면 약 2분입니다.
> 교실에서 친구들이 돌아가며 하려면 짧은 쪽이, 이야기를 촘촘히 담으려면 긴 쪽이 좋습니다.
> 몇 단계로 할까요? (숫자만 말해줘도 됩니다)

같이 물어볼 것:
- **한 단계가 몇 초쯤이면 좋을지** (또는 한 판 전체 목표 시간)
- 단계마다 **다른 장면/배경**이 나오게 할지 (단계가 넘어가는 게 눈에 보이면 훨씬 재미있다)

받은 답은 코드에서 **배열 하나 + 상수 하나**로 만든다. 나중에 학생이 숫자만 바꿔서
단계를 늘리거나 줄일 수 있어야 한다.

```js
var STAGE_MS = 15000;              // 한 단계 길이 (여기만 바꾸면 전체 길이가 바뀐다)
var STAGES = [ /* 학생이 정한 단계 수만큼 */ ];
```

## 1단계. 5년 뒤를 같이 그린다

게임 이야기를 하기 전에 **미래부터** 묻는다. 여기서 나온 답이 그대로 게임의 재료가 된다.
아래 5개를 한 번에 던지고, 답하기 어려운 건 건너뛰어도 된다고 말해준다.

1. **5년 뒤 어느 하루의 한 장면** — 어디에 있고, 뭘 하고 있고, 옆에 누가 있나?
   (거창한 목표 말고 진짜 장면 하나)
2. **그때의 내가 "해냈다"고 느낀다면 무엇 때문일까?** 반대로 **가장 후회할 것 같은 건?**
3. **거기까지 가려면 반드시 통과해야 하는 관문**은? 계속 **소모되는 것**(시간·체력·용기)은?
   **방해하는 것**은?
4. **갈림길이 있다면** 어떤 갈래들이 보이나? 각 갈래 끝의 5년 뒤는 어떻게 다른가?
5. **이 게임을 한 친구가 무엇을 느꼈으면 좋겠나?**

### 답을 게임 재료로 옮겨 보여준다

답을 그대로 두지 말고 아래처럼 **표로 정리해서** 학생에게 확인받는다. 이때도 장르는 말하지 않는다.

| 이야기에서 나온 것 | 게임에서 될 수 있는 것 |
|---|---|
| 계속 소모되는 것 (2·3번 답) | 목숨 / 게이지 / 남은 시간 |
| 꼭 지켜야 하는 것 | 놓치면 손해 보는 것 |
| 하고 싶지만 위험한 것 | 점수는 크지만 대가가 있는 것 |
| 관문·사건 (3번 답) | **단계** — 0단계에서 정한 개수에 맞춰 배치 |
| 갈림길 (4번 답) | 플레이 방식에 따라 달라지는 결과 |
| 남기고 싶은 느낌 (5번 답) | 점수 계산식이 무엇을 칭찬할지 |

**그다음에** 묻는다: "이 재료로 **어떤 게임**을 만들고 싶어요?"
학생이 형태를 말할 때까지 기다린다. 정말 모르겠다고 하면 그때만 2~3개를 한 줄씩 제시한다.

## 2단계. 규칙을 줄인다 — 숫자는 2개까지

학생이 형태를 정하면, 만들기 전에 규칙을 **한 줄로 말할 수 있는지** 확인한다.

> "떨어지는 걸 받는다. 끝." / "부딪히면 죽는다. 끝."

화면에 계속 보이는 **숫자는 2개 이하**로 한다. 3개를 넘어가면 학생 본인도 헷갈리고,
플레이하는 친구는 뭘 해야 할지 모른다. 이야기를 다 담으려다 규칙이 늘어나는 게
이 작업에서 가장 흔한 실패다. **이야기는 배경과 단계 제목으로 담고, 규칙은 최대한 적게 둔다.**

## 3단계. 만든다

`public/works/<슬러그>/game5.html` **한 파일**로 만든다. 빌드 도구도, 외부 라이브러리도 쓰지 않는다
(교실 노트북에서 파일 하나만 열면 돌아가야 한다).

지켜야 할 기술 규칙 — 이건 정답이 정해져 있으니 네가 알아서 처리한다:

- **조작은 방향키와 손가락 둘 다** 되게 하고, **속도를 똑같이** 맞춘다.
  마우스·손가락이 순간이동하면 다 잡을 수 있어서 게임이 성립하지 않는다.
  그리고 **마지막에 쓴 입력만 듣게** 한다. 안 그러면 마우스를 한 번 움직인 뒤로
  방향키를 눌러도 캐릭터가 제자리로 끌려간다.
- **화면 크기**: 게임판을 고정 크기로 그리고 `position:absolute` + `transform: translate(-50%,-50%) scale(s)`
  로 화면에 맞춘다. 폭을 고정한 채 두면 **폰에서 가로로 삐져나간다.**
- **소리**는 파일 없이 `AudioContext` 로 짧은 8비트 효과음을 만든다(선택).
- 설정값(단계 수·길이·점수)은 파일 **맨 위에 상수로 모아두고 주석**을 단다.
  학생이 나중에 혼자 숫자를 바꿔볼 수 있어야 한다.

## 4단계. 봇으로 밸런스를 잰다 ⚠️ 건너뛰지 마라

**"설계 의도"와 "실제로 플레이했을 때"는 거의 항상 다르다.** 눈으로 몇 번 해보는 것으로는
못 잡는다. 자동으로 플레이하는 봇을 만들어 **여러 판을 돌려 점수 분포를 본다.**

`node` 로 게임 스크립트를 그대로 실행하는 하니스를 만든다. DOM 을 흉내 내고
`requestAnimationFrame` 대신 시계를 직접 돌리면 한 판이 수십 ms 만에 끝난다.

```js
// game5.html 의 <script> 를 꺼내 Node 에서 돌린다
const code = fs.readFileSync(SRC, 'utf8').match(/<script>([\s\S]*?)<\/script>/)[1];
// 테스트용 계측(실제 파일은 건드리지 않는다)
const patched = code.replace('var G = null;', 'var G = null; window.__peek = function () { return G; };');
// document/window/fetch/localStorage 를 흉내 낸 객체를 만들고 vm 으로 실행 →
// rAF 큐를 33ms 씩 손으로 돌리면서 봇이 조작 이벤트를 넣는다
```

**실력이 다른 봇을 최소 3종류** 돌린다: 안전 위주 / 적당히 욕심 / 과욕. 그리고 확인한다:

| 확인할 것 | 실패 신호 | 실제로 겪은 예 |
|---|---|---|
| 플레이 방식에 따라 점수가 갈리는가 | 어떻게 놀아도 점수·결과가 비슷하다 | 조작이 순간이동이라 다 잡혀서 전부 같은 결과가 나왔다 |
| 위험한 선택에 보상이 있는가 | 안전하게만 해도 최고점이 나온다 | |
| 규칙을 어기는 게 이득은 아닌가 | **꼭 지켜야 할 것을 버리는 쪽이 점수가 높다** | 아기를 버리고 점수템만 먹다 죽는 게 이득이라, 완주 보너스를 넣어 뒤집었다 |
| 한 판 길이가 목표와 맞는가 | 0단계에서 정한 시간과 다르다 | |
| 초보가 너무 빨리 끝나지 않는가 | 30초 만에 게임 오버 | 목숨 3개는 너무 빡빡해서, 단계마다 하나씩 돌려주게 했다 |

**결과를 학생에게 표로 보여주고**, 숫자를 어떻게 고칠지 같이 정한다. 네가 혼자 고치고
"밸런스 맞췄어요" 하지 마라 — 이 조정 과정이 이 수업에서 제일 배울 게 많은 부분이다.

## 5단계. 랭킹을 붙인다 (서버 수정 불필요)

기록 API 는 이미 만들어져 있다(`server/games.js`). **`gameKey` 만 새로 정하면** 작품별로
기록이 따로 쌓인다. 서버 코드를 고치지 마라.

| 부르는 곳 | 하는 일 |
|---|---|
| `POST /api/game/me` | 내가 로그인 사용자인지 게스트인지. `{ token }` → `{ needsName, nickname }` |
| `POST /api/game/score` | 점수 저장. `{ gameKey, token, playerName, score, grade, detail }` |
| `GET /api/game/ranking?gameKey=...` | 기록 보기. **로그인 없이 누구나** |

지켜야 할 것:

- **`gameKey`** 는 영문 소문자·숫자·하이픈만. `<슬러그>-game5` 형식을 권한다 (예: `park-game5`).
  오타가 나면 랭킹이 둘로 갈라진다.
- **로그인 사용자**는 이름을 묻지 말고 바로 저장한다. 서버가 **본인 닉네임으로만** 기록하므로
  남의 이름을 보내도 사칭되지 않는다.
- **게스트/비로그인**은 끝난 뒤 **이름을 입력받아야** 저장된다. 이름을 안 써도 **기록 보기는 된다.**
- 토큰은 `localStorage.getItem('yw_token')` 로 읽는다(같은 서버라 그냥 읽힌다).
- **기록 보기 버튼은 시작 화면과 결과 화면 양쪽에** 둔다. 기록은 언제든 볼 수 있어야 한다.
- `/api/game/me` 응답을 **기다렸다가** 이름칸을 띄울지 정한다. 안 기다리면 응답이 늦을 때
  로그인한 사람에게도 이름을 묻게 된다.
- 등급·칭호를 넣을지는 **학생이 정한다.** 점수만 쓰겠다고 하면 `grade` 는 빈 문자열로 보낸다.

## 로컬 서버 띄우기 ⚠️ 백그라운드로 띄우면 죽는다

랭킹도 갤러리도 **서버가 켜져 있어야** 확인할 수 있다. 확인이 필요해지면 이렇게 띄운다.

```bash
npm start        # http://localhost:3000
```

**가장 확실한 방법은 사용자가 직접 띄우는 것이다.** 프롬프트에 `!npm start` 를 입력하면
대화창 안에서 실행되고 세션과 무관하게 계속 살아 있다. 사용자에게 이렇게 안내해도 좋다.

에이전트가 직접 띄워야 한다면 **반드시 분리된 세션으로** 띄운다.
`npm start &` 나 `nohup ... &` 로 띄운 서버는 **대화 턴이 끝날 때 프로세스 그룹째 정리되어
조용히 죽는다**(로그에 오류 없이 SIGTERM 만 남는다. 실제로 두 번 죽었다).
`detached: true` 가 POSIX 의 `setsid()` 를 불러 새 세션을 만들어 준다.
macOS 에는 `setsid` 명령이 없으니 node 로 대신한다.

```bash
node -e "
const { spawn } = require('child_process');
const fs = require('fs');
const out = fs.openSync('/tmp/youngworld.log', 'a');
const c = spawn(process.execPath, ['server/index.js'], {
  cwd: process.cwd(), detached: true, stdio: ['ignore', out, out],
  env: Object.assign({}, process.env, { PORT: '3000' }),
});
c.unref();
console.log('서버 PID:', c.pid);
"
sleep 3
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:3000/    # 200 이면 정상
```

- **살아 있는지 확인**: `curl -s -o /dev/null -w '%{http_code}' http://localhost:3000/` → `200`
- **포트가 이미 물려 있으면**: `lsof -nP -iTCP:3000 -sTCP:LISTEN` 로 확인한다.
  이미 떠 있으면 새로 띄우지 말고 그대로 쓴다.
- **재시작이 필요할 때**: `seed.js` 는 서버가 켜질 때 돌기 때문에, 갤러리 등록을 반영하려면
  껐다 켜야 한다. `pkill -f "node server/index.js"` 후 위 명령을 다시 실행한다.
- **DB(`youngworld.db`)를 함부로 지우지 마라.** 서버를 껐다 켜는 것만으로 충분하다.
  지우면 그 사람이 남긴 랭킹 기록과 아바타 설정이 사라진다.
- 쿼리스트링을 쓸 때는 **따옴표로 감싼다** — zsh 에서 `?` 가 글로브로 먹혀 실패한다.
  `curl "http://localhost:3000/api/game/ranking?gameKey=park-game5"`

## 6단계. 갤러리에 걸고 검증한다

`server/seed.js` 의 `STUDENT_GAMES` 배열에 **한 줄만** 추가한다. 사람마다 코드 블록을
복사하지 마라.

```js
{ nickname: '박효진', slug: 'park', title: '박효진의 <게임 이름>' },
```

- `nickname` 은 **DB 아바타 이름과 정확히 같아야** 한다(다르면 조용히 건너뛴다).
- `slug` 는 `public/works/<슬러그>/` 폴더명. ASCII 소문자·숫자·하이픈만.
- 등록 URL 은 `/works/<슬러그>/game5.html` — `isSafeDocUrl()` 이 하위 폴더를 막는다.

### 완료 전 체크리스트

1. **`game5.html` 을 커밋했는가** — 파일이 없으면 `seed.js` 가 등록을 건너뛴다.
2. **닉네임이 DB 와 일치하는가**
   ```bash
   node -e "console.log(require('./server/db').Avatars.all().map(a=>a.nickname))"
   ```
3. **실제로 걸리는지**
   ```bash
   npm start   # 다른 터미널
   node -e "
   const {Avatars,Gallery}=require('./server/db');
   const a=Avatars.byNickname('<닉네임>');
   console.log(Gallery.all().filter(w=>w.author_id===a.id).map(w=>w.slot+' → '+w.url));
   "
   ```
4. **두 번 켜도 중복되지 않는지** (멱등)
5. **랭킹 3가지 경로를 실제로 눌러 확인**
   - 로그인 상태로 한 판 → 내 닉네임으로 자동 기록되는가
   - 게스트로 한 판 → 이름칸이 뜨고, 입력하면 저장되는가
   - 로그인 안 한 채 **기록 보기**만 → 목록이 보이는가
6. **폰 크기에서 가로로 안 넘치는가** — 폭 360px 짜리 iframe 에 띄워 확인한다.
7. **눈으로 확인** — 교실 입장 → 작품 구역 → 이름표 클릭 → `🎮 5년 뒤 나의 미래` 카드가
   `✔ 전시됨` 인지 → 눌러서 플레이되는지.

배포는 `git pull` 후 재시작이라(`deploy/deploy.sh`), **서버가 재시작돼야 등록된다.**
DB(`youngworld.db`)는 git 밖의 파일이라 배포로 덮어써지지 않는다.
